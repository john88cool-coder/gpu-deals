# HANDOFF — gpu-deals: контекст для продолжения работы

Документ для модели AI, которая продолжит этот проект на другом компьютере.
Написан по итогам полной сессии разработки: дизайн согласован с владельцем,
система работает в продакшене. Читайте целиком перед любыми изменениями.

Дата передачи: 2026-09-03. Состояние: бот работает на GitHub Actions, сутки
автономной работы без падений.

---

## 1. Что это и зачем

Бот мониторит цены на видеокарты в 7 интернет-магазинах Казахстана и присылает
в Telegram не факт скидки, а **оценку того, действительно ли цена хорошая**.
Ключевое требование владельца: магазины рисуют фейковые «скидки» (у Technodom
«-18%» стоит на трети каталога, а позиция с «-41%» продаётся дороже аналога без
скидки), поэтому магазинная скидка **никогда не является основанием для алерта** —
только справочная строка в тексте сообщения.

Владелец покупает карту себе, разовая покупка, горизонт 1-2 месяца (решено в
интервью; см. раздел «Журнал решений»).

## 2. Контекст владельца

- Система владельца: Ryzen 7 2700X, 16 ГБ DDR4-2666, ASUS PRIME X470-PRO,
  EVGA RTX 2070 SUPER XC ULTRA (уточнено владельцем 2026-09-06; в сравнениях
  PassMark — 18 122 балла). Апгрейд платформы вероятен — поэтому готовые
  сборки отслеживаются наравне с картами.
- Бюджеты: **600 000 ₸ мягкий потолок на карту** (выше — не молчать, а помечать
  превышение), **1 000 000 ₸ жёсткий на готовую сборку**. «Чем дешевле, тем лучше».
- **Критерий отбора: память больше 8 ГБ** (добавлено 2026-09-06). Позиции с
  8 ГБ и ниже, и сборки с такой картой, не собираются вовсе — их нет ни в базе,
  ни в уведомлениях (`Thresholds.skip_memory_gb = 8`). RTX 3080 на 10 ГБ
  проходит. За «неизвестным» объёмом может прятаться 16 ГБ, поэтому такие
  позиции остаются. До введения правила 174 из 422 отправленных уведомлений
  были про 8-гигабайтные карты.
- Telegram-бот: @VideoCardPlease_bot, chat_id `366256716`.
- Владелец принял стиль работы: агрессивный режим уведомлений (лучше лишнее
  сообщение, чем пропущенная находка), честные отчёты об ошибках, все пороги —
  числа, которые можно крутить.

## 3. Быстрый старт

```bash
uv sync --extra dev --extra dns   # зависимости + Playwright
uv run playwright install chromium
uv run pytest                      # 146 тестов, сеть не нужна
uv run gpu-deals crawl --console   # полный обход, вывод в консоль
```

Переменные окружения (см. `.env.example`; локальный `.env` в git НЕ входит):

```

TELEGRAM_CHAT_ID=366256716
GPUDEALS_DB=...          # по умолчанию src/gpudeals/data/prices.sqlite3
```

Файл `.env` приложение само не читает: `python-dotenv` в зависимостях нет,
`config.py` берёт значения строго из окружения. Локально — `set -a; . ./.env;
set +a`, на VPS — `EnvironmentFile=` в systemd, в CI — секреты репозитория.

Репозиторий: `https://github.com/john88cool-coder/gpu-deals` (public).
Локальный файл `.gh_token` (PAT, права repo+workflow, истекает ~2026-10-02)
в git не входит — на новой машине либо создайте новый PAT, либо используйте
браузерный вход Git Credential Manager.

**Дисциплина пуша**: CI сам коммитит базу после каждого обхода. Перед любым
пушем с локальной машины обязательно `git pull --rebase` — иначе конфликт
с CI-коммитом. Не правьте ничего в `data/prices.sqlite3` руками без нужды:
это живая история цен.

## 4. Как оценивается «хорошая цена»

Три независимых сигнала (пороги в `config.py`, class Thresholds):

| Сигнал | Условие | Основание сопоставления |
|---|---|---|
| «упало» | цена ниже медианы за 14 дней на ≥3% | партномер = та же модель |
| «дешевле аналогов» | ниже медианы класса на ≥7% | класс «чип + объём памяти» |
| «новинка в бюджете» | позиция впервые под потолком | — |

Принципиальные решения в оценке:

- **Тренд, а не исторический минимум.** Рынок памяти растёт (дефицит DRAM,
  RTX 3060 подорожала на 45% за два месяца — Tom's Hardware, 27.08.2026).
  Сравнение с минимумом прошлого навсегда заглушило бы сигнал.
- **Ключ позиции привязан к магазину**: `"{shop}:pn:{part_number}"` и т.д.
  Одна карта у Technodom и Kaspi — два предложения; без магазина в ключе их
  истории смешиваются, а уведомление о более дешёвом подавляется как повтор.
- **Медианы классов считаются раздельно для карт и сборок** (kind=card/build):
  сборка за 870 000 ₸ иначе задерёт медиану класса «rtx5070-12».
- Сигнал «упало» требует ≥7 наблюдений на позицию (min_observations_for_trend);
  при обходе раз в 2 часа это ~сутки накопления.
- Дедупликация: повторный алерт по позиции — только при новом снижении.
  Рост цены пишется в базу молча.
- Наблюдения сохраняются ПОСЛЕ оценки позиции, иначе текущая цена попадает в
  собственную историю и размывает сигнал.
- В медиану класса позиция не входит сама: `class_prices(exclude_identity=...)`
  выкидывает её прошлые наблюдения. Иначе упавшая карта сравнивалась бы со своей
  же прежней ценой и падение выглядело бы выгоднее, чем оно есть.
- Одна позиция даёт одно наблюдение за обход. Каталоги отдают повторы: sulpak на
  номер страницы за границей каталога возвращает последнюю доступную, forcecom
  переставляет товары между страницами между запросами. Пока это не отсекалось, у
  позиции sulpak накопилось 321 наблюдение против 40 у technodom, и порог в 7
  наблюдений набирался копиями одного снимка. Общий помощник —
  `shops/paging.py: new_offers()`.

## 5. Архитектура

```
src/gpudeals/
  config.py      пороги, бюджеты, watchlist (WatchedModel: query + class_key)
  models.py      Offer, ItemKind(card/build), MatchLevel(part_number/class)
  normalize.py   извлечение чипа/памяти/партномера/бренда; валидация VRAM
  storage.py     SQLite: observations, alerts, crawls; retention 30 дней + VACUUM
  evaluate.py    три сигнала, Verdict
  report.py      сборка текста (HTML для Telegram, с экранированием), дайджест
  notify.py      Notifier: TelegramNotifier (нарезка по 4000 симв.) / Console
  benchmarks.py  цена за балл PassMark (статический CSV, 31 модель)
  crawler.py     цикл: эталонные магазины сохраняются первыми, потом оценка;
                 send_heartbeat() читает сводку из базы, обхода не делает
  cli.py         crawl / watchlist / heartbeat
  shops/         7 парсеров, общий интерфейс SHOP/parse(html)/fetch(client)
  shops/paging.py  new_offers(): один identity — одно наблюдение за обход
tests/           146 тестов на сохранённых фикстурах (сеть не нужна)
deploy/          systemd-юниты для VPS (не используются, пока живём на Actions)
.github/workflows/  crawl (2ч), watchlist (20мин), heartbeat (03:00 UTC), tests
```

Роли магазинов: `ALERT_SOURCE = False` у kaspi и e-katalog — они эталоны рынка
(питают медианы и минимумы, но алертов не порождают). Остальные пять —
источники алертов. Эталонные сохраняются в базу ДО оценки остальных.

## 6. Разведка по магазинам (главная ценность — не потерять)

| Магазин | Способ | Особенности |
|---|---|---|
| technodom.kz | `__NEXT_DATA__` JSON в HTML | два каталога: карты (3 стр.) + компьютеры (9 стр., мониторы отбрасываются по отсутствию GPU). Партномер — в квадратных скобках названия, у 100% позиций |
| shop.kz | JSON в `data-product` каждой карточки | партномер в `item_variant`; полный каталог 58 стр. → берём фильтр RTX 50 (8 стр.) + стр. 1 общего |
| sulpak.kz | data-атрибуты плиток | старой цены нет вовсе; **`data-price="0.0"` у «под заказ» — обязательно пропускать** (нули портили минимумы рынка) |
| forcecom.kz | microdata schema.org | в названии 2 группы скобок: спецификация `[16 ГБ, GDDR7...]` и партномер `(GV-...)` — шаблоны вендоров применяются РАНЬШЕ разбора скобок. robots: Crawl-delay 5 |
| kaspi.kz | `GET /yml/product-view/pl/filters?text=...&page=0&ui=d` + заголовки `X-KS-City: 750000000` | 12 карточек за запрос; точечно по watchlist, пауза 10 с (robots). Старой цены не отдаёт: unitPrice==unitSalePrice всегда, promo:true у всех |
| e-katalog.kz | `<tr class="model-short-row">`, `/list/189/` | агрегатор: диапазон цен продавцов, берём нижнюю границу. Истории цен НЕТ (проверено) |
| dns-shop.kz | headless Chromium (Playwright) | единственный магазин с браузером: Cloudflare-челлендж обычному HTTP. Цены ленивые: приходят позже карточек, на стр. 2+ — после прокрутки. Подменять User-Agent обязательно (штатный Playwright ловит челлендж) |

robots.txt: у DNS `Disallow: /catalog/markdown/*` — раздел уценки **не парсим
принципиально**. Kaspi просит Crawl-delay: 10, forcecom 5 — соблюдаем.

**Пагинация DNS не работает** (проверено 2026-09-06): запрос `?page=2` в
прогретой сессии отвечает челленджем Cloudflare (HTTP 403, «Just a moment...»),
а в свежем контексте браузера — HTTP 200 с содержимым ПЕРВОЙ страницы. Не
верьте «валидному HTML» — сверяйте количество новых identity. Покрытие добирается
страницами-подборками `/catalog/recipe/<id>/<модель>/` по моделям с памятью
больше 8 ГБ (90 позиций вместо 22). Каждая загрузка — свежий контекст браузера;
идентификаторы сняты с первой страницы каталога, при смене их нужно перенабрать
оттуда же.

## 7. Нормализация — где живут грабли

- **Валидация VRAM по конфигурациям чипа** (`_VRAM_CONFIGS`): «RTX 5070»
  существует только на 12 ГБ → «RTX 5070 / 32 Гб» в названии сборки — это
  оперативная память, не видеопамять. Чипы с двумя конфигурациями (5060 Ti:
  8/16) при неуказанном объёме остаются БЕЗ класса — угадывать нельзя, позиция
  просто выпадает из сравнения аналогов.
- **RTX 5060 = только 8 ГБ** (не смотрите на витрины: Technodom продаёт
  «RTX 5060 16GB» — это их ошибка, скобочный партномер говорит 8G).
- Партномер: шаблоны вендоров (GV-, NE-, DUAL-/PRIME-/TUF-/ROG-, Nxxxx-) →
  затем квадратные скобки. Скобки с запятой/ГБ/GDDR/БИТ — спецификация,
  не партномер. Пробелы из партномера удаляются (иначе магазины не матчятся).
- Память в названии берётся сразу после чипа; перед DDR/SSD/HDD — это ОЗУ.

## 8. Инфраструктура

**GitHub Actions, public репозиторий** (= бесплатные минуты). База
`data/prices.sqlite3` коммитится CI после каждого обхода — так история цен
живёт между запусками. Retention 30 дней (глубже ничего сигналам не нужно).
Браузер Playwright кэшируется actions/cache.

Секреты репозитория: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — уже настроены.

**Известная проблема платформы**: cron Actions задерживается и отбрасывается.
Фактическая частота за сутки наблюдений: обходы каждые 4-7 ч вместо 2 ч,
watchlist 6 раз вместо 72, сводка с опозданием 5 ч. **Watchlist на Actions
свого смысла не выполняет** (та же частота, что у полного обхода).

Развилки (обсуждено с владельцем, решения нет):
- остаться бесплатно с медленным ритмом (текущее состояние, владельца пока
  устраивает мониторинг-дайджест);
- либо VPS hoster.kz Cloud 1-2-25 (3 800 ₸/мес, Караганда, казахстанский IP
  желателен для Kaspi/DNS) — юниты готовы в `deploy/`, README содержит план.

1. **Токен бота: отозван 6 сентября.** Прежний токен из истории чата больше не
   работает (`getMe` → 401). Новый выдан BotFather, но он тоже прошёл через чат,

   ещё раз и внести токен руками в Secrets репозитория и локальный `.env`, минуя

   отправлять сообщения**: `crawl` упадёт на шаге отправки в тот обход, где
   появится находка, и шаг «Сохранить базу» после него не выполнится.
2. DNS: стабильно отдаёт только страницу 1 (~22 позиции). Страницы 2+ с ценами
   через раз. Не гоняйтесь за Cloudflare — договорились брать, что отдают.
3. Watchlist задан предположительно (rtx5060ti-16, rtx5070-12, rtx5070ti-16,
   rx9070-16, rx9070xt-16) — правится в `config.py` без трогания кода.
4. Сигнал «упало» на живых данных ещё не срабатывал ни разу. Учтите: до 6
   сентября порог в 7 наблюдений у sulpak и forcecom набирался копиями одного
   снимка (см. раздел 4), поэтому накопленная история этих двух магазинов
   недостоверна. Первый честный выстрел — через сутки после дедупликации.
5. Справочник PassMark обновляется руками раз в квартал
   (`src/gpudeals/data/gpu_benchmarks.csv`).
6. База в git растёт: 972 КБ → 10 МБ за четыре дня, 11 коммитов в сутки. VACUUM
   после retention добавлен, но он начнёт освобождать место только на 30-й день.
   Если репозиторий станет тяжёлым, альтернатива — `actions/cache` вместо
   коммитов; это меняет модель «история цен живёт в коммитах» и требует решения
   владельца.

## 10. Чего НЕ делать (решения с обоснованиями)

- **Не доверять `oldPrice`/`discount` магазинов** для решений — только справочно.
- **Не реализовывать WhatsApp**: вне 24-часового окна — модерируемые Meta платные
  шаблоны, Казахстан с 01.10.2026 переводится на повышенный тариф; неофициальные
  Baileys/whatsapp-web.js нарушают ToS и рискуют личным номером владельца.
  Абстракция Notifier оставлена для второго канала.
- **Не парсить `/catalog/markdown/` DNS** — robots.txt.
- **Не сравнивать нечётко названия** (fuzzy) — у GPU одна цифра меняет модель.
- **Не смешивать карты и сборки** в медианах классов.
- Цена за производительность показывается только относительно («на 14% лучше
  медианы класса») и только когда не сработал сигнал «дешевле аналогов»
  (внутри класса это одно и то же число) и разница ≥5%.
- Не добавлять магазины/сложность без запроса владельца — улучшения растут из
  реальных уведомлений.

## 11. Журнал ключевых решений (сжатый)

Дизайн согласован в четыре раунда интервью с владельцем:

1. Разовая покупка; сигналы: кросс-магазинное сравнение + тренд, цена за балл
   как контекст, ручной потолок как фильтр.
2. Сбор всего каталога без фильтра, алерты — современные карты; состояние
   товара не различаем; полный обход + watchlist; агрессивный режим.
3. Telegram (WhatsApp отклонён по фактическим данным); Kaspi — эталон; холодный
   старт: (b) с первого дня, история подключается per-item; матчинг
   партномер→класс; пороги 3%/7%/600k; «мёртвый выключатель» парсеров.
4. Готовые сборки: остаток за платформу = цена сборки − рыночный минимум карты;
   без порога (число показывается, решает человек); бюджета 1M; схема БД с
   полями kind/class_key заложена сразу.

Баги, найденные живыми данными (не повторять): нули sulpak; ключ без магазина;
партномер Gigabyte с прилипшим объёмом; «-41%» дороже аналога; память DDR в
классе GPU; спецификация forcecom как партномер; лимит Telegram 4096; каталог
sulpak, отдающий последнюю страницу вместо пустой на номер за границей; forcecom,
переставляющий товары между страницами между запросами.

## 13. Изменения 6 сентября 2026

Разведка по живым страницам и правки по её итогам:

- **Повторы в истории цен.** Одна позиция за обход писалась в базу до 3.4 раза
  (sulpak 171 строка на 51 позицию, forcecom 82 на 59). Причины: каталог sulpak
  из пяти страниц на запрос `?page=7` отдаёт последнюю доступную вместо пустой;
  forcecom переставляет товары между страницами между запросами. Добавлен
  `shops/paging.py: new_offers()`, все семь парсеров ведут множество виденных
  identity, обход страниц прекращается на первой странице без новых позиций.
  У sulpak появился `total_pages()` по `data-pagesCount`. Проверено смок-обходом:
  554 строки / 554 identity по шести магазинам.
- **Критерий «память больше 8 ГБ»** (решение владельца). Позиции ≤8 ГБ и сборки
  с такой картой не собираются вовсе: фильтр в `crawler.crawl()` после загрузки,
  порог `Thresholds.skip_memory_gb = 8`. Таблица `crawls` при этом пишет СЫРОЕ
  число позиций парсера — тревога «вернул 0» не должна молчать, когда магазин
  жив, но весь ассортимент отфильтрован. Обход пишет ~480 позиций вместо ~600.
  История ≤8 ГБ, накопленная раньше, в базе осталась и выйдет с retention.
- **DNS: покрытие 22 → 90 позиций.** Пагинация каталога не работает (детали в
  разделе 6), вместо неё — страницы-подборки по моделям с памятью больше 8 ГБ,
  каждая в свежем контексте браузера. Мёртвый цикл по `?page=N` убран.
- **Экранирование.** Названия, ссылки, метки наличия и имена магазинов проходят
  через `html.escape`: сообщения уходят с `parse_mode=HTML`.
- **VACUUM.** `storage.compact()` вызывается после реального удаления
  retention-ом; `auto_vacuum` в базе выключен, без сжатия файл навсегда сохранял
  бы размер пика.
- **Heartbeat больше не делает обход.** `crawler.send_heartbeat()` читает итоги
  из таблицы `crawls`; из workflow убраны Playwright и Chromium, timeout 25 → 10
  минут.
- **Медиана класса** больше не включает саму оцениваемую позицию
  (`class_prices(exclude_identity=...)`); прежде фильтр шёл по значению цены.
- **CI прогоняет тесты** (`.github/workflows/tests.yml`) на push и PR.
- **Рейтинг PassMark в уведомлениях** (добавлено 2026-09-06). Справочник
  `gpu_benchmarks.csv` теперь генерируется автоматически: workflow
  `benchmarks.yml` раз в месяц качает две открытые страницы
  videocardbenchmark.net (high_end + mid_range, полный рейтинг ~3000 карт) и
  коммитит CSV; руками обновлять больше не нужно. В справочник попадают только
  десктопные RTX/RX (~110 записей) — то, что бот видит; ноутбучные,
  «Max-Q» и китайские «D»-варианты отбрасываются, иначе они сталкиваются с
  десктопными картами в одном классе или ломают откат по чипу. Матчинг по
  class_key (с памятью: у PassMark 5060 Ti 8GB и 16GB — разные позиции).
  `format_rating()` в report.py печатает строку «Балл PassMark: … (N-е из M
  десктопных RTX/RX), в X раз быстрее вашей RTX 2070 SUPER»; карта владельца —
  `owner_gpu_class_key`/`owner_gpu_name` в config.py. Сломанный справочник не
  роняет уведомление — строка просто не показывается. Покрытие последнего
  обхода: 25 из 27 классов (без рейтинга остаются рабочие RTX 5000/Quadro
  варианты — чип неразличим).
- **technodom `_MAX_PAGES` 9 → 10**: категория компьютеров отдаёт 10 страниц,
  одна страница сборок терялась.
- Мелочи: убран дублирующийся `import re` в `ekatalog.py`, удалена неиспользуемая
  `sulpak.has_next_page`.

Инструменты локально: на машине не было ни Python, ни uv — установлен uv в
