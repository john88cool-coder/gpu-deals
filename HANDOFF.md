## 1. Что это и зачем

Бот мониторит цены на видеокарты и готовые сборки в **девяти** интернет-магазинах
Казахстана и присылает в Telegram не факт «скидки», а **оценку того, действительно
ли цена хорошая**.

Ключевое требование владельца: магазины рисуют фейковые «скидки» (у Technodom
«-18%» стоит на трети каталога, а позиция с «-41%» продаётся дороже аналога без
скидки). Поэтому магазинная скидка **никогда не является основанием для алерта** —
только справочная строка в тексте. Основания — собственная история цен и
сравнение с рынком.

Задача владельца: разовая покупка, горизонт 1–2 месяца. Бот спроектирован под
эту задачу и не претендует на универсальность.

```bash

uv run playwright install chromium

uv run gpu-deals crawl --console   # полный обход, вывод в консоль
```

Переменные окружения (см. `.env.example`; локальный `.env` в git НЕ входит):

```
TELEGRAM_BOT_TOKEN=...   # от @BotFather
TELEGRAM_CHAT_ID=366256716
GPUDEALS_DB=...          # по умолчанию src/gpudeals/data/prices.sqlite3
```

Файл `.env` приложение само не читает: `python-dotenv` в зависимостях нет,
`config.py` берёт значения строго из окружения (`set -a; . ./.env; set +a`
локально, `EnvironmentFile=` в systemd, секреты репозитория в CI). Приложение
оценивает переменные **на момент импорта модуля** — `GPUDEALS_DB` нужно ставить
до запуска.

Дисциплина пуша: CI сам коммитит базу после каждого обхода — перед пушем с
локальной машины обязательно `git pull --rebase`. В `data/prices.sqlite3`
руками ничего не править: это живая история цен.

Инструменты локальной машины (на момент 2026-09-06): Python и uv не были
установлены — uv поставлен в `~/.local/bin`
(`curl -sSL https://astral.sh/uv/install.sh | sh`); прежний `.venv` ссылался на

истекает ~2026-10-02) лежит на диске, в git не входит.

## 4. Как оценивается «хорошая цена»

Сигналы в `evaluate.py` (пороги в `config.Thresholds`). Все работают по
`(тип товара, класс)` — карты и сборки никогда не смешиваются.

| Сигнал | Условие | Основание |
|---|---|---|
| «упало» (PRICE_DROP) | цена ниже медианы этой позиции за 14 дней на ≥3% | нужен партномер; ≥7 наблюдений |
| «дешевле аналогов» (BELOW_CLASS) | ниже медианы класса за 3 дня на ≥7% | класс «чип + объём», ≥3 соседа |
| «новинка в бюджете» (NEW_IN_BUDGET) | впервые под потолком и без истории за 14 дней | — |
| «целевая цена» (TARGET_PRICE) | цена ≤ `target_price` класса из watchlist | личная цель владельца |
| «в наличие» (RESTOCK) | позиция вернулась на витрину по цене ≤ цели | сравнение с последней записью |

Принципиальные решения (нарушать только с пониманием):

- **Тренд, а не исторический минимум.** Рынок памяти растёт; сравнение с
  минимумом прошлого навсегда заглушило бы сигнал.
- **Ключ позиции привязан к магазину**: `"{shop}:pn:{part_number}"`,
  `"{shop}:sku:{sku}"` или `"{shop}:title:{title}"`. Одна карта у двух магазинов
  — два предложения. У forcecom и alfa sku берётся из стабильного URL — у
  позиций без партномера identity больше не зависит от правок заголовков.
- **Одна позиция — одно наблюдение за обход** (`shops/paging.py: new_offers()`).
  Каталоги отдают повторы: sulpak на номер страницы за границей каталога
  возвращает последнюю доступную страницу, forcecom переставляет товары между
  страницами между запросами, DNS на `?page=2` отдаёт содержимое первой. Пока
  это не отсекалось, позиция sulpak набрала 321 наблюдение против 40 у
  technodom, и порог «7 наблюдений» набирался копиями одного снимка.
- **Наблюдения сохраняются ПОСЛЕ оценки** — иначе текущая цена попадает в
  собственную историю.
- **Позиция не сравнивается сама с собой**: `class_prices(exclude_identity=...)`.
- **Медианы и минимумы — только по позициям в наличии.** Цена «под заказ» — не
  рыночная цена.
- **Отсутствующие товары пишутся в базу, но не алертят.** Строка «Наличие» в
  сообщении — только когда товара нет.
- **Ресток обходит дедупликацию.** Обычно повторный алерт — только при цене
  строго ниже последней отправленной; но «вернулся в наличие по цели» — новость,
  которую терять нельзя (`restocked` в гейте crawler).
- **Кросс-магазинное сравнение** («Дешевле сейчас: dns — 450 000 ₸» /
  «Самая низкая цена среди магазинов») считается из офферов ТЕКУЩЕГО цикла, не
  из базы: цена трёхдневной давности отвечает на «где было дешевле», а не «где
  сейчас». В Verdict несёт (магазин, цена, URL) — URL идёт в кнопку.
- Кнопки дайджеста вешаются на последний кусок нарезанного сообщения и строятся
  по находкам (`crawler._alert_buttons`). Ошибка здесь роняла боевой обход —
  покрыто тестом `test_telegram_buttons_go_to_last_chunk_only`.

## 5. Архитектура

```
src/gpudeals/
  config.py        INTERESTED_CHIPS, пороги (skip_memory_gb, бюджеты, порог
                   поломки), watchlist (WatchedModel: query + class_key +
                   target_price), owner_gpu, UA, пути
  models.py        Offer, ItemKind(card/build), MatchLevel(pn/class);
                   Offer.identity = магазин + pn|sku|title
  normalize.py     чип/память/партномер/бренд из названия; _VRAM_CONFIGS
  storage.py       SQLite (observations, alerts, crawls); class_prices/
                   class_floor_for_cards/class_best_offers (только in_stock,
                   exclude_identity); last_successful_crawl, last_in_stock,
                   best_build_residual; prune 30 дней + compact() (VACUUM);
                   shop_summary (для heartbeat)
  evaluate.py      5 сигналов, Verdict (signals, class_median, cheaper_elsewhere,
                   lowest_in_market, build_residual, over_budget_by)
  report.py        format_offer/digest/breakage/heartbeat/market_digest/
                   buyers_guide; MarketDigest, DigestDeal, DigestValue;
                   html-экранирование (_text)
  notify.py        Notifier (send(text, buttons)); Telegram: нарезка по 4000
                   симв., кнопки на последний кусок; Console: печатает кнопки
  benchmarks.py    рейтинг PassMark: parse_rating_pages, refresh (2 запроса),
                   rating_for (class_key → chip-fallback при единственной
                   записи), format_rating (+сравнение с картой владельца)
  backtest.py      python -m gpudeals.backtest: прогон порогов по истории
                   с симуляцией дедупликации
  dashboard.py     render(conn, out): статический HTML (инлайн-SVG) для Pages
  crawler.py       crawl (фильтры: watchlist, чип+память; shop_minima цикла;
                   оценка alert-источников; ресток-гейт), run_once,
                   send_heartbeat (сводка + шпаргалка), send_digest,
                   send_watchdog
  cli.py           crawl | watchlist | heartbeat | digest | watchdog |
                   render-dashboard | refresh-benchmarks
  shops/           9 парсеров: technodom, shop_kz, sulpak, forcecom, kaspi,
                   e-katalog, dns, alfa, halyk; paging.py (new_offers)
  data/            gpu_benchmarks.csv (генерируется), prices.sqlite3 (git)
tests/             198 тестов на сохранённых фикстурах (сеть не нужна)
deploy/            systemd-юниты + install.sh для VPS
.github/workflows/ crawl, catchup, watchlist, heartbeat, digest, dashboard,
                   watchdog, benchmarks, tests
```

Схема БД: `observations` (все поля Offer + observed_at, kind, identity —
индексы по identity/class/времени), `alerts` (identity PK → цена/дата), `crawls`
(итоги по магазинам, ok/error). Retention наблюдений — 30 дней, потом VACUUM.

## 7. Нормализация — где живут грабли

- **Валидация VRAM по конфигурациям чипа** (`_VRAM_CONFIGS`): «RTX 5070»
  существует только на 12 ГБ → «RTX 5070 / 32 Гб» в названии сборки — это
  оперативная память. Двухконфигурационные чипы (5060 Ti: 8/16) при
  неуказанном объёме остаются БЕЗ класса — угадывать нельзя.
- **RTX 5060 = только 8 ГБ** (витринная ошибка Technodom; скобочный партномер
  правдивее).
- **Память после числа проверяется контекстом ДО числа**: «DDR5 32Гб» — ОЗУ
  (скидывается), «16GB/DDR5 32Гб» — первое число валидно. Порядок «8 Гб» после
  чипа — паттерн alfa.
- **Партномер**: шаблоны вендоров (GV-, NE-, DUAL-/PRIME-/TUF-/ROG-, Nxxxx-) →
  затем квадратные скобки. Скобки с запятой/ГБ/GDDR/БИТ — спецификация, не
  партномер. Пробелы удаляются (иначе магазины не матчятся).
- **alfa: «6144 Mb» → ГБ** перед извлечением (`_memory_to_gb`), иначе класс не
  строится.
- Не добавляйте чипы в интересы без проверки `_VRAM_CONFIGS`: чипа нет в
  словаре — любой объём 4–32 ГБ считается правдоподобным (см. RTX 5000/Quadro).

## 8. Инфраструктура

**GitHub Actions, public репозиторий.** Восемь workflow:

| Workflow | Расписание (UTC) | Что делает |
|---|---|---|
| crawl | `7 */2 * * *` | полный обход 9 магазинов, оценка, Telegram, коммит базы |
| catchup | `23 * * * *` | hourly: полный обход только если база старше 4 ч (`--if-stale-hours 4`); concurrency-группа `crawl` — с crawl не пересекается |
| watchlist | `*/20 * * * *` | точечная проверка watchlist (без DNS, без записи crawls) |
| heartbeat | `0 3 * * *` | строка о живости + шпаргалка покупателя; читает базу |
| digest | `0 4 * * 1` | недельный дайджест рынка; читает базу |
| dashboard | `10 4 * * 1` | статический HTML → GitHub Pages |
| watchdog | `0 6,18 * * *` | тревога, если последний успешный обход старше 12 ч |
| benchmarks | `23 5 8 * *` | обновление справочника PassMark (2 запроса) |
| tests | push/PR | pytest |

Секреты: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` — обновлены владельцем
2026-09-05 после отзыва скомпрометированного токена. Playwright кэшируется
actions/cache (только в workflow с браузером).

**Известная проблема платформы**: cron Actions задерживается и отбрасывается —
фактическая частота обхода 4–7 ч вместо 2. Catch-up смягчает, но не решает.
**Решение — VPS hoster.kz Cloud 1-2-25 (3 800 ₸/мес, Караганда; казахстанский
IP желателен для Kaspi/DNS/Halyk)**: юниты и `deploy/install.sh` готовы,
миграция = клон + `.env` + запуск скрипта. После VPS: watchlist реально раз в
20 минут, целевые цены проверяются быстро, интерактивные команды боту становятся
возможными. Обсуждено с владельцем, решение пока не принято.

**Рост базы в git**: 972 КБ → ~11 МБ за 4 дня, ~11 коммитов/сутки. Retention
30 дней + VACUUM сдерживают файл, но git-история растёт монотонно. Если станет
тяжело — `actions/cache` вместо коммитов (меняет модель «история живёт в
коммитах»; решение владельца).

## 9. Незакрытые хвосты

1. **VPS** — единственное структурное решение вне кода; всё готово
   (`deploy/install.sh`, юниты, README), ждёт владельца.
2. **Локальный `.env` содержит мёртвый токен** (старый, отозванный). На CI не
   влияет; для ручных запусков с доставкой обновить. Токен в Secrets актуален.
3. **Локальный `.env` не читается приложением** — только экспорт в окружение
   (`set -a; . ./.env; set +a`).
4. **История sulpak/forcecom до 6 сентября недостоверна** (дубли см.
   раздел 4) — их тренды корректны только после этой даты.
5. **Сигнал «упало» ещё ни разу не срабатывал честно** — первый выстрел покажет,
   не шумят ли пороги 3%/14 дней; при сомнениях — `python -m gpudeals.backtest`.
6. **DNS-подборки захардкожены** (`_RECIPE_PATHS`): идентификаторы снимаются с
   первой страницы каталога; при смене — перенабрать.
7. **База в git растёт монотонно** (см. раздел 8) — альтернатива `actions/cache`
   требует решения владельца.
8. **`.gh_token`** (PAT, repo+workflow) истекает ~2026-10-02 — после этого пуш с
   этой машины перестанет работать.

## 10. Чего НЕ делать (решения с обоснованиями)

- **Не доверять `oldPrice`/`discount` магазинов** для решений — только
  справочная строка.
- **Не ходить в PassMark при отправке уведомления** — справочник локальный,
  обновляется ежемесячным workflow; сетевой запрос в горячем пути — точка
  отказа, а баллы меняются раз в месяцы.
- **Не реализовывать WhatsApp**: вне 24-часового окна — платные шаблоны Meta,
  Казахстан с 01.10.2026 на повышенном тарифе; Baileys/whatsapp-web.js
  нарушают ToS. `Notifier`-абстракция оставлена для второго канала.
- **Не парсить `/catalog/markdown/` DNS** и любые `?…` URL DNS — robots.txt.
- **Не сравнивать названия нечётко** — одна цифра меняет модель.
- **Не смешивать карты и сборки** — ни в медианах, ни в сравнении «где дешевле».
- **Не добавлять магазины/сложность без запроса владельца** — и не предлагать
  витрины без живой разведки (урок alser/mechta: предложены, не существуют).

## 13. Как продолжать

1. Прочитать этот документ целиком; разделы 4, 6, 7 — перед любым изменением
   парсеров или сигналов.
2. `git pull --rebase` (CI коммитит каждые 1–2 часа).
3. `uv sync --extra dev --extra dns && uv run playwright install chromium`.
4. `uv run pytest` — 198 тестов, зелёные, прежде чем менять код.
5. Изменения парсеров проверять живым смоком на scratch-базе
   (`GPUDEALS_DB=/tmp/... uv run gpu-deals crawl --shop X`), затем тестами
   на фикстурах.
6. Пуш, дождаться зелёного `tests`, при необходимости — dispatch нужного
   workflow и проверка результата в проде.
7. Новые фичи — через короткое согласование дизайна с владельцем (как в этой
   сессии: разведка → дизайн → «да» → код → смок → пуш).
